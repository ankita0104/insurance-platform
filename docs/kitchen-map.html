The Data Engineering Kitchen

The whole field, as one kitchen

Every "scary skill" is just a station in a kitchen that turns raw data into finished answers. ✅ = you've already used it. For any new tool you meet, just ask: "which station is this?"

Delivery door → Fridge → Prep & cook → Plating → Safety check → Serve  |  across all: head chef, the building, the recipe book

The 6 stations (the data's journey)

🚪 1. Delivery door — getting data IN (ingestion)

The back door where ingredients are delivered.

REST API ✅ — pull data from another system over the internet.
Files (CSV, etc.) ✅ — data dropped as files (your claims). Most common in enterprises.
Kafka — a conveyor belt for data arriving continuously (real-time).
AWS Firehose / Kinesis — Amazon's version of that conveyor belt.
Airbyte / Fivetran — ready-made connectors so you don't hand-code ingestion.
AWS Glue — managed tool that can ingest and transform.
How they differ: Files/API = batch (chunks). Kafka/Firehose = streaming (continuous). Airbyte/Fivetran = pre-built connectors vs writing your own loader.

🧊 2. Fridge — storing data

Where you keep ingredients until you cook.

Data Warehouse — organized fridge for fast SQL analysis: Snowflake ✅ (your job), BigQuery, Redshift.
Data Lake — cheap storage for raw files of any kind: S3.
Lakehouse — both at once: Databricks, via Delta Lake / Apache Iceberg.
Database (OLTP) — the small fast fridge an app uses live: Postgres, MySQL.
How they differ: Warehouse = structured + fast SQL (analysis). Lake = cheap + any format. Lakehouse = both. Database = runs the live app, not analytics.

🔪🍳 3. Prep & cook — transforming data (the biggest station)

Washing, chopping, and cooking raw ingredients into dishes.

SQL ✅ — the core language for shaping data. The knife every cook needs.
dbt ✅ — organizes SQL transforms (tested, documented) inside the warehouse.
Python ✅ — general-purpose glue for custom logic.
Apache Spark / PySpark — industrial stove for cooking enormous data across many machines.
Databricks — a managed kitchen built around Spark.
Scala — alternative Spark language (PySpark more common).
Hadoop / Hive / HBase — the old industrial stove (pre-Spark). Legacy; know the words only.
How they differ: dbt = SQL transforms on data already in a warehouse. Spark/PySpark = heavy lifting on massive data too big for one machine. Python = custom glue. Hadoop = the outdated Spark.

🍽️ 4. Plating & menu — data modeling

Arranging food so it's easy to order and serve.

Dimensional (Kimball) ✅ — star schema (fact + dimensions), built for easy analytics.
3NF / Normalization — split data to avoid duplication; for live apps (OLTP).
SCD (Slowly Changing Dimensions) — track history when something changes.
Data Vault — complex enterprise method for huge, audited orgs.
How they differ: Normalization = no redundancy, for apps. Dimensional = easy querying, for analytics. Data Vault = enterprise history. SCD = the "remember the past" technique.

🔬 5. Food-safety inspector — data quality (your superpower)

Checking food is safe before it leaves.

dbt tests ✅ — rules in your transforms (not null, unique, allowed values).
Observability ✅ — monitoring data health over time (freshness/volume/schema/distribution).
Great Expectations / Soda / Deequ — dedicated data-quality frameworks.
How they differ: dbt tests = quick rules during transform. GE/Soda = specialized heavier DQ tools. Observability = watching trends to catch "something looks off."

🍴 6. Serving the customer — consumption / BI

The finished dish on the customer's table.

Power BI / Tableau — dashboards for non-technical people.
Looker — similar, with a modeling layer (Google).
Superset — free, open-source dashboards.
RAG / GenAI — serving data to AI to answer questions (your medical project!).
How they differ: Power BI/Tableau/Superset/Looker all make dashboards — just different vendors. RAG = serving data to an AI instead of a human.

The roles that run across the whole kitchen

👨‍🍳 The head chef — orchestration

Coordinates which station runs when, and restarts failed ones.

Airflow — industry-standard (code-based), most common in job posts.
Prefect ✅ — simpler, more Pythonic (you used this).
Azure Data Factory — Microsoft's, more drag-and-drop.   Dagster — modern newcomer.
How they differ: all schedule + run pipelines. Airflow = standard, Prefect = friendlier, ADF = Azure/GUI, Dagster = new.

🏢 The building & utilities — cloud

The premises everything runs in.

AWS — most common. Services: S3 (storage), Glue (ETL), Lambda (run code on demand), Redshift (warehouse).
Azure — Microsoft's cloud (common with Databricks).   GCP — Google's (BigQuery).
How they differ: three competing providers, same concepts. Learn one (AWS) deeply; the rest transfer.

📖 The recipe book & engineering discipline

Tracked recipes, consistent process, portable setup.

Git / GitHub ✅ — track every change (your repo).
CI/CD — automatically test code every time you change it.
Docker — package your setup so it runs identically anywhere.
Terraform (IaC) — set up cloud infrastructure with code instead of clicking.
How they differ: Git = history, CI/CD = auto-testing, Docker = portability, Terraform = building the cloud setup.

🔧 The knife skills — languages used everywhere

SQL ✅ (asking data questions)  ·  Python ✅ (general logic)  ·  Scala (Spark alternative).
The calm takeaway: count your ✅'s — you've touched a station in almost every row. The "big scary list" of 30+ tools collapses into 6 stations + 4 cross-roles. Any new tool you meet, just ask: "which station is this?" — and you'll instantly know what it does and what it compares to. You are not behind. There is no race.
