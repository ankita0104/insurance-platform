The learning curve — what order to approach it

Build on what you have. Each phase is job-ready on its own; don't jump ahead.

Phase 0 — Foundation ✅ (you have this)

The base everything else builds on.

  • SQL, Python, dbt, dimensional modeling, data quality, Git, idempotent/incremental pipelines, Prefect orchestration.

Phase 1 — Core modern stack (next, high ROI)

Finishes the "modern data engineer" profile. All on your current plan.

  • PySpark (distributed processing) — in progress
  • Docker (containerization)
  • CI/CD (GitHub Actions — auto-test on push)
  • Airflow (industry-standard orchestration; you know the concepts via Prefect)

Phase 2 — Cloud + big-data platform (the big unlock)

This is where most senior postings live. Pick ONE cloud, go deep.

  • AWS core data services — S3, Glue, Redshift, Lambda, IAM
  • Databricks — managed Spark platform (very high demand)
  • Delta Lake / Lakehouse / Iceberg — table formats & architecture

Phase 3 — Streaming + advanced modeling

Rounds out real-time + deeper design questions.

  • Kafka + Spark Structured Streaming (real-time, watermarks, late data)
  • Data modeling depth — 3NF, SCD, Data Vault
  • Snowflake optimization — performance, cost, clustering

Phase 4 — Rounding out (as roles require)

Pick up on demand based on specific job targets.

  • A BI tool (Power BI or Looker), Terraform (IaC), Great Expectations/Soda
  • GenAI/RAG for data (your medical-RAG project already starts this)
  • Optional: Scala, Flink, Kubernetes
The one-line strategy: finish Phase 1 (modern stack) → then commit to Phase 2 (AWS + Databricks) — that combination is what turns "solid data engineer" into "highly employable across the market you're seeing." Don't spread thin across all clouds/tools; go deep on one path.
